The `SinglePaneStepperV2` is a single-column guided flow for conversational setup. It keeps the vertical stepper timeline from the original [Single Pane Stepper](https://harness-design.netlify.app/growth-patterns/single-pane-stepper/) — checkmarks, connectors, and step badges — but completed answers render as chat messages.

After a step is completed, the form is not collapsed into an accordion. The question stays in the timeline as the step header, and the selection appears as a user `MessageBubble` with edit, copy, and a timestamp.

Use this version for onboarding and PLG flows where the thread of answers should read like a conversation.

## What changed from v1

| v1 Single Pane Stepper                                                    | v2                                                   |
| ------------------------------------------------------------------------- | ---------------------------------------------------- |
| Completed card content collapses in an accordion under the step           | Completed card content is replaced by a chat message |
| Restart lives in the step header / accordion chrome                       | Edit and copy live on the message footer             |
| Same `FlowConfig` + `useFlowCard` engine as the dual / split pane stepper | Same `FlowConfig` and `useFlowCard` API in this repo |

## Usage

```typescript jsx
import { SinglePaneStepperV2, useFlowCard } from "@harnessio/ui/components";
import type { FlowConfig } from "@harnessio/ui/components";

function GoalCard() {
  const { complete } = useFlowCard();

  return (
    <SinglePaneStepperV2.Card
      title="What do you want your first flag to do?"
      description="In a sentence or two, describe what functionality you want your first feature flag to control."
    >
      <textarea />
      <button
        onClick={() =>
          complete({
            answer: "Switch a Sign Up button from blue to green, or change its copy, for a subset of users.",
          })
        }
      >
        Continue
      </button>
    </SinglePaneStepperV2.Card>
  );
}

const flow: FlowConfig = {
  steps: {
    goal: { title: "Goal" },
    targeting: { title: "Targeting" },
  },
  subSteps: {
    goal: { step: "goal", component: GoalCard, next: "targeting" },
    targeting: { step: "targeting", component: TargetingCard },
  },
  initialSubStep: "goal",
};

<SinglePaneStepperV2.Root
  flow={flow}
  contentTitle="Create your first feature flag"
  onComplete={(state) => console.log("Done!", state)}
/>
```

## Anatomy

```typescript jsx
<SinglePaneStepperV2.Root flow={flowConfig}>
  {/* Cards are rendered automatically from flowConfig.subSteps */}
</SinglePaneStepperV2.Root>
```

Cards still use `useFlowCard` to complete, skip, error, or open drawers:

```typescript jsx
function MyCard() {
  const { complete } = useFlowCard();

  return (
    <SinglePaneStepperV2.Card title="Choose an option">
      <button onClick={() => complete({ answer: "Option A" })}>Option A</button>
    </SinglePaneStepperV2.Card>
  );
}
```

## Chat answers

Pass a string `answer` in `complete()` so the message survives remounts and back-navigation:

```typescript jsx
complete({ provider: "github", answer: "GitHub" });
```

You can also pass `answer` on the card. The card resolves display text in this order:

1. The `answer` prop on `SinglePaneStepperV2.Card`
2. `answer` stored on the completed history entry
3. `stateSnapshot.answer`

When a step is **active** or **errored**, the card renders `children` (the form). When it is **completed**, `children` are not shown — only the question header and the chat message. There is no accordion expand/collapse for the completed question.

Completed messages include:

- Edit — reactivates the step after the same confirmation dialog used by the split-pane stepper
- Copy — copies the answer text
- Timestamp — local time from when `complete()` ran

## Best practices

1. Always send `answer` from `complete()` with a human-readable label, not a raw id (`"A subset of users"` instead of `"subset"`).
2. Keep one question per card so the thread stays readable.
3. Do not rebuild accordion or completed-form UI inside the card — v2 owns the completed state.
4. Use `SinglePaneStepperV2` for conversational setup. Use `SplitPaneStepper` when users need a persistent rail and a larger workspace.

## Accessibility

- Active steps use `aria-current="step"`
- Completed indicators are buttons that request reactivation
- Message edit is labeled `Edit this answer`
- Copy uses the existing `CopyButton` control
- The go-back confirmation dialog is the same warning `AlertDialog` used by the split-pane stepper
